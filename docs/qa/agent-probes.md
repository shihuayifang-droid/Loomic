# Agent 能力探针集（QA-07）

> 用途：用一组**固定、可复述**的混合需求，回归 Agent 的端到端能力（意图解析 → 工具选择 → 产出形态 → 计费），
> 让「这一版 Agent 到底能不能干活」有可复算的答案，而不是靠感觉。
>
> 六模态 × 3 条 = 18 条探针。每条都给出「判定要点」，写的是可以脚本检查的东西；
> 只有「人工复核点」列里的内容才需要人眼判断。
>
> 本文档只写方法，不含任何账号、密钥或内部地址。真实调用一律在**测试账号**下进行，详见「怎么跑」。

## 通用约定

- **探针 ID** 是稳定标识，增删探针只允许追加新 ID 或作废旧 ID，不得改号（历史记录要能对齐）。
- **输入需求原文** 必须原样复制进每次冒烟记录，不改写、不简写 —— 改一个字就是另一条探针。
- **期望产出形态** 写的是「必须出现的产物种类与数量」，不是风格偏好。
- **判定要点** 全部可用命令或断言检查：文件存在性、扩展名、像素尺寸、时长、页数、MIME、字段非空。
- 每条探针跑完必须记录：探针 ID、开始时间、结束时间、**实际消耗积分**、重试次数、判定结果。
  积分从计费记录里取真实值，不填估算值。

## 怎么跑

1. **只用测试账号**。测试账号与真人账号必须分开：真人账号不做探针，测试账号不对外服务。
   跑之前确认当前登录身份是测试账号；身份不对就停下，不要用真人账号「先跑一条看看」。
2. **按 ID 顺序一条一条跑**，一条跑完再看下一条。不要并发跑多条 —— 并发会让「哪条探针烧了积分」无法归因。
3. **每条探针记录消耗积分**：从计费记录取该时间段内该任务的真实积分增量，写进冒烟记录。
   积分不是从任务轮次数推算出来的，也不填估算值。
4. **超 200 分即按护栏中止**。单任务累计消耗超过 200 分时，护栏返回中止码，该任务不再继续花钱；
   此时**不要重试绕过护栏**，直接把这条探针记为「预算中止」，写清中止时的累计积分，继续下一条。
5. 每条探针的判定要点用命令或断言检查，结果只有「通过 / 不通过 / 预算中止」三种，不写「基本可以」。
6. 跑完把结果按「探针 ID / 是否通过 / 消耗积分 / 重试次数 / 失败原文」汇总成一张表附在记录末尾。

## 预算口径

- **单次冒烟上限：200 分 / 每任务**。这是护栏的默认阈值，也是单条探针的天花板；宁可把一条探针拆细，也不许调高上限去迁就一条需求。
- **整轮冒烟上限：18 条 × 单条上限** 是理论上限；经验上不会打满，但预算按理论上限预留，不按「平时大概花多少」预留。
- **失败重试次数上限：每条探针 2 次**（即首次 + 2 次重试，共 3 次尝试）。
  同一输入在同一环境重试 2 次仍失败 → 记为「不通过」，附三次的失败原文，不再重试；**重试也计费**，上限按累计积分算，不按单次算。
- 触到「单任务超 200 分」或「重试上限」任一条件即停该条探针，不叠加继续试。
- 一次冒烟的总消耗必须可从计费记录复算：记录表里的「消耗积分」列求和应等于该时间段测试账号的积分下降总量，对不上就说明有未归因的消耗，先查清再继续。

## 维护

- 新增探针：追加新 ID（不要复用已作废的 ID），并补全五列。
- 需求原文变了 → 是**新探针**，不是改旧探针。
- 某条探针长期不稳定、判定要点又说不清 → 先修判定要点（让它更可机检），修不好就作废该条。
