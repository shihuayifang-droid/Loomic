# Web 无障碍扫描（axe-core / QA-10）

本目录的 `a11y.spec.ts` 用 [`@axe-core/playwright`](https://github.com/dequelabs/axe-core-npm) 对
`apps/web` 的主要页面做自动化无障碍扫描。约定（testid 定位、禁坐标点击、全部 `/api/**` mock）
沿用 `README.md`，扫描范围与门槛以本文件为准 —— **改 spec 里的区域映射或门槛要同步改这里**。

## 1. 扫描范围

| 页面 | 路由 | 区域 | 区域选择器（`AxeBuilder.include`，均为 testid） |
|---|---|---|---|
| 登录页 | `/login` | 整页 | `html` |
| 首页 | `/home` | 工具条 | `[data-testid^="home-prompt-"]` |
| 首页 | `/home` | 面板（发现区） | `[data-testid^="home-discovery-"]` |
| 首页 | `/home` | 菜单 | `[data-testid="agent-model-selector-trigger"]` |
| 画布（工作区页面） | `/canvas?id=…` | 工具条 | `[data-testid^="canvas-tool-menu-tool-"]` |
| 画布（工作区页面） | `/canvas?id=…` | 菜单 | `[data-testid="main-menu-trigger"]`、`[data-testid="dropdown-menu-button"]`、`[data-testid="canvas-zoom-dropdown"]`、`[data-testid="brand-kit-selector-trigger"]`、`[data-testid="agent-model-selector-trigger"]` |
| 画布（工作区页面） | `/canvas?id=…` | 对话区 | `[data-testid^="chat-"]` |
| 画布（工作区页面） | `/canvas?id=…` | 面板（图片生成面板） | `[data-testid="canvas-image-generator-panel"]` |

### 区域映射为什么用 testid 前缀

工单要求「每个区域用 `AxeBuilder(...).include(<该区域 testid>)`」，但**这几个区域的容器本身没有
`data-testid`**（给容器补 testid 要改组件，超出本工单的 4 文件白名单）。因此区域按「容器内控件的
testid 前缀」划定，仍然是 testid 定位，没有 CSS 结构选择器、没有坐标：

- 首页输入条 / 发现区：`home-prompt-*`、`home-discovery-*`。
- 画布左侧工具条：`canvas-tool-menu-tool-*`（选择 / 矩形 / 椭圆 / 箭头 / 直线 / 自由绘制 / 文本 / 图片 / 手型）。
- 画布菜单：几个菜单**入口**（主菜单、更多、缩放、品牌套件、模型）。展开后的菜单浮层没有独立
  容器 testid，所以菜单区域扫的是入口本身。
- 对话区：`chat-*`（会话选择器、技能列表、输入区、发送按钮等）。
- 登录页没有上述任何区域的容器 testid，改为整页扫描。

Excalidraw 自带的 `toolbar-*` 工具条在本应用的布局里被隐藏（`offsetParent === null`，改用
`canvas-tool-menu`），所以不参与扫描。

## 2. 判定门槛

- 规则集：`withTags(["wcag2a", "wcag2aa", "wcag21a", "wcag21aa"])` —— 只取 WCAG 2.0 / 2.1 A + AA，
  不让 `best-practice` 规则混进门槛。
- **`impact` 为 `critical` 或 `serious` 的违规必须为 0**。
- `moderate` / `minor` 允许存在，但必须逐条登记在第 4 节的已知问题表里；每次运行也会把本区域
  完整结果打到控制台（`A11Y-scan …` 一行，含 `blocking` / `recorded`），便于核对是否新增。
- 存在 `critical` / `serious` 的区域**不 disableRules、不放宽门槛**：对应的用例用 `test.fixme`
  停用，并在第 3 节作为待修项登记。修好之后再删掉 `test.fixme`（改 `A11Y.md` 同步删掉该行）。

## 3. 待修项（critical / serious，均为 `test.fixme`）

| # | 规则 ID | 影响 | 区域 | 元素 / 说明 | 是否计划修 |
|---|---|---|---|---|---|
| R1 | `color-contrast` | serious | `/login` 整页（3 个节点） | 登录页左侧特性列表 `li:nth-child(1..3)`（"Use password, magic link, or Google sign-in" 等三条），白色圆点与小字在浅色底上对比度不足 | 是，需组件侧改配色 |
| R2 | `label-content-name-mismatch` | serious | `/home` 面板（发现区，8 个节点） | `home-discovery-case-*` 卡片按钮：`aria-label`（如 "Vintage Car Poster"）与卡片内可见标题不一致 | 是，需统一 aria-label 与可见标题 |
| R3 | `button-name` | critical | `/canvas` 对话区（1 个节点） | `chat-input-send`：只有图标的发送按钮，禁用态下没有可访问名称（无 `aria-label` / `title`） | 是，需补可访问名称 |
| R4 | `button-name` | critical | `/canvas` 面板（图片生成面板，1 个节点） | 面板里 `min-w-12` 的提交按钮（`canvas-image-generat*`），禁用态下没有可访问名称 | 是，需补可访问名称 |

当前通过门槛（无 critical / serious）的区域：首页工具条、首页菜单、画布工具条、画布菜单。

## 4. 已知问题表（moderate / minor）

本次扫描在上述 8 个区域里**没有** `moderate` / `minor` 违规：`a11y.spec.ts` 每次运行输出的
`A11Y-scan …` 行中，通过门槛的 4 个区域 `recorded` 字段为空数组；被 `test.fixme` 停用的 4 个区域
只有第 3 节列出的 `critical` / `serious` 条目。

| 规则 ID | 影响 | 区域 | 说明 | 是否计划修 |
|---|---|---|---|---|
| （无） | — | — | 本次 `withTags` 规则集下没有 moderate / minor 违规 | — |

以后出现 `moderate` / `minor` 时，每条都要在该表登记「规则 ID / 影响 / 区域 / 说明 / 是否计划修」。
需要页面级结构规则（`region`、`landmark-one-main`、`page-has-heading-one` 等 `best-practice` 规则）
的话，另起工单扩规则集 —— 它们不在本工单的 WCAG A/AA 门槛里。

## 5. 范围限制

**完整 WCAG 合规需辅助技术人工测试与专业评审。** axe-core 是自动化规则检查：它只能发现一部分
可程序化判定的问题（对比度、可访问名称、标签、ARIA 用法等），无法覆盖键盘操作全流程、屏幕阅读器
实际播报、焦点顺序是否合理、动效与阅读障碍等。本目录的扫描结果是「自动化能查出来的部分」，
不能当作 WCAG 合规结论。

## 6. 怎么跑

```bash
# 先构建静态导出（e2e 只服务 apps/web/out，不编译）
pnpm --filter @loomic/web build

# 整个 e2e（含本扫描）
pnpm --filter @loomic/web e2e

# 只跑本扫描
pnpm --filter @loomic/web e2e a11y.spec.ts
```

被 `test.fixme` 停用的用例不会执行，运行时计入 `skipped`；要重新打开某一条，删掉它的
`test.fixme` 前缀即可。
